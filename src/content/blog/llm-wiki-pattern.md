我有一柜子资料：194 份，328MB。调研报告、对话记录、简历草稿、学习笔记、SOP、话术库。

这些东西以前的状态是「存着」。存着的意思是：我知道它在，但我不记得里面有什么，所以它约等于不存在。

直到有一天我想明白一件事 —— 让我懒得维护知识库的不是阅读和思考，是**记账**。

## 人工维护知识库为什么会崩

你认真维护过个人 wiki 就会懂这个曲线。

一开始很爽。读了份好资料，写个摘要页，连上几个相关页面，很有成就感。

然后负担开始长：新资料进来了，得更新相关页面；某个数字改了，得回头改所有引用它的地方；两个月前写的结论和今天的想法冲突了，得标注出来。

**负担是线性增长的，价值不是。** 写到第 30 页的时候，你每写 1 页新内容要顺带改 3 页旧内容 —— 这时候大多数人就停了，wiki 变成一堆过期的半截页面。

我停过两次。

## 换个思路：不做 RAG，做「编译」

第一个想到的方案是 RAG（检索增强生成）：把资料切片向量化，提问时检索拼装。

这方案能用，但有个根本问题 —— **它没有积累**。

| | RAG | LLM 维基模式 |
|---|---|---|
| 知识在哪 | 原始文档切片 | 已编译的知识库页面 |
| 每次提问 | 重新检索 + 拼装 | 读已有页面 + 综合 |
| 有没有积累 | 无 | **有，可以复利** |
| 交叉引用 | 无 | 已经建好了 |
| 矛盾冲突 | 无感知 | 已标注 |

问一百次，它就检索一百次，第 100 次的回答不会比第 1 次更聪明。资料之间的连接从未被真正建立起来。

我想要的不是「查得到」，是**越用越厚**。

所以改成：让大模型**增量编译**一套互链的 markdown 页面。知识编译一次，之后每次提问、每份新资料都让它更厚一点。

## 三层架构

```
原始资料层  ——  不可变，是唯一的真相来源（source of truth）
     ↓
知识层      ——  智能体全权维护，人只读
     ↓
规则层      ——  一份 AGENTS.md，让智能体成为守纪律的维护者
```

**原始资料层**不能改。这一条是底线 —— 大模型会在编译过程中「优化」掉它觉得不重要的细节，而那些细节常常是三个月后你要找的东西。原始件必须留着，编译产物错了还能重来。

**知识层**是人只读的。听起来有点极端，但理由很实在：一旦你自己动手改，就要承担记账成本，这套体系立刻退化回人工维护。我要的是「提问和拍板」，不是「编辑」。

**规则层**是最关键的一层。没有它，大模型就是个通用聊天机器人：你让它摄入一份资料，它给你写一篇漂亮总结，然后不更新索引、不连相关页面、不改冲突的旧结论。AGENTS.md 里写清楚分类规则、页面模板、摄入流程、引用格式，它才是个守纪律的维护者。

## 三种操作

**摄入（Ingest）**：读来源 → 写摘要页 → 更新相关实体/概念/专题页 → 刷新索引 → 记流水日志。一份资料通常牵动 10-15 个页面。这个工作量我手动做会崩溃，它一轮就改完。

**提问（Query）**：先读索引定位候选页，再深入读页面，回答必带 `[[引用]]`。

这里有个我一开始没设计、后来补上的关键动作：**把好答案回填成新页面**。否则这次探索的成果，会随着聊天窗口关闭一起蒸发。现在我每问出一个有价值的结论，就让它落成一张概念页。

**体检（Lint）**：查矛盾、陈旧表述、孤儿页、缺失页面、数据缺口，顺带告诉我下一步该研究什么。

体检是这套系统最值钱的功能。它帮我抓出来过一个我自己绝不会发现的问题：五份简历里团队规模写了三个不同数字（20-30 人 / 50+ 人 / 约 100 人）。人工维护时，这种冲突就静静躺在库里，直到某天在面试现场被戳穿。

## 为什么它不会崩

回到开头那句话：知识库真正累人的是记账 —— 更新交叉引用、保持摘要最新、记录矛盾。

这些活儿的特点是：**枯燥、量大、要求一致性**。

大模型不会腻，不会漏改，一轮能同时改十几个文件，而且每次都按同一套规则来。**维护成本趋近于零**，wiki 因此能一直保鲜。

我现在的库是 77 页，从概念/实体/专题/来源四个维度分类，每页带 `updated` 和 `status`。跑起来之后，我这边的工作变成了三件事：往 `原始资料/` 丢文件、说一句「摄入」、提问。

## 几个还没解决的问题

不想把这套东西说得多完美，有几条是明摆着的：

1. **规模上限未验证。** 现在 77 页，靠一份内容索引就能定位。超过 300 页还行不行，我不知道 —— 到时候可能得引入本地搜索。
2. **冲突处理能力有限。** 大模型倾向于「和稀泥」，把冲突双方并列了事。我在规则里明确要求「并列双方证据 + 标注冲突」，但判断哪个对，仍然是我的活。
3. **编译会丢细节。** 摘要必然有损。所以原始资料层必须保留，这条不能妥协。
4. **它会顺着我的偏见走。** 我的库里「已定」的结论，有几条其实只是我自己的判断，缺乏外部验证。看自己库的结论要保持警惕。

## 最后

如果你也在攒资料、也停过两次，可以试试这个思路。

核心不是「用 AI 写笔记」—— 那是另一个东西。核心是**把记账成本外包掉，把自己解放到提问和判断上**。

人的那部分，从来不该是维护。
